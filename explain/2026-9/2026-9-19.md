**原因链**(现在被 Casey 的原话确认了):

```

      → DefWindowProc 执行 DestroyWindow
      → 触发 WM_DESTROY → 我们的 case 里 PostQuitMessage(0)
      → 队列里出现 WM_QUIT → GetMessage 返回 0
      → 消息循环结束 → WinMain 返回 → 进程退出
```

## 二、Day 2 Q&A 要点

### 1. 他在 Q&A 里**当场动手改的代码**

| 他做了什么 | 说明 |
|---|---|
| **给字符串函数加 `A` 后缀** | `RegisterClass` → `RegisterClassA`;后来又补了 `GetMessageA`、`DispatchMessageA`(`TranslateMessage` 没有 A/W 版本)。理由:**别人用 Unicode 设置编译你的源码时不会报错** |
| **把类样式整个删掉** | 先删 `CS_HREDRAW \| CS_VREDRAW`,再删 `CS_OWNDC`,最后说"整个 `style` 都不要了,我们不在乎,没问题" ← 今天照做了 |
| **演示 `SetPixel`** | 有人问"最快把像素放到屏幕上的办法",他当场写 `SetPixel(设备上下文, 100, 100, 颜色)`,看到一个小点;随即说**太慢,游戏绝不能用**,明天展示真正的做法 |
| **解释 `case` 为什么必须加大括号** | 观众报错 "initialization of variables in WM_PAINT case is skipped"。原因:case 里的变量不用 `{}` 包住就处在 **switch 的作用域**里,跳到别的 case 会**跳过它们的初始化**,所以编译器警告 |
| **演示 `for(;;)` 比 `while(1)` 好在哪** | 把警告等级调到 `/Wall`,`while(1)` 立刻报 **"conditional expression is not constant"**,`for(;;)` 不报。顺便发现 `/Wall` 会让**Windows 自己的头文件**刷出一大片警告,于是又关掉 |
| **现场单步调试消息循环** | 在 `GetMessage → TranslateMessage → DispatchMessage` 上下断点,看调用栈穿过 `user32.dll` → `ntdll` → **回到自己的 `WindowProc`** |
| 发现 Windows 会**绕过消息队列直接调用**你的窗口过程 | 例如消息号 `0x7F`(`WM_GETICON`)、`0xC0F9`(49401)。**这就是"为什么必须 `RegisterClass` 注册回调"的根本原因** —— 系统要能在任何时候找到你的函数 |
