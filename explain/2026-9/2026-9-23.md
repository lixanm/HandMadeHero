## 三、今天发现的两个问题(都在你代码里,AI **只报没动**)

### 3.1 ⚠️ stub 的 `return 0` 语义反了

`winerror.h` 里的真值(已核对):

```c
#define ERROR_SUCCESS                0L
#define ERROR_DEVICE_NOT_CONNECTED   1167L
```

所以 stub(`56 行` / `66 行`)返回 **0 = "成功"**,而调用点写的是 `if (dwResult == ERROR_SUCCESS) { /* 手柄已连接 */ }`
→ **程序会认为"手柄永远插着"**,然后去读一个被 `ZeroMemory` 清成全 0 的状态。

现在因为那些 `bool Up / AButton / StickX` 还没被使用,看不出后果;但语义上 **stub 的职责是回答"我没有设备"**,Casey 的 stub 是 `return(ERROR_DEVICE_NOT_CONNECTED);`。

### 3.2 ⚠️ `Win32LoadXinput()` 少了"取不到就退回 stub"的兜底

现在的写法:

```c
XInputGetState = (x_input_get_state*)GetProcAddress(XInputLibrary,"XInputGetState");
XInputSetState = (x_input_set_state*)GetProcAddress(XInputLibrary,"XInputSetState");
```

- **DLL 都加载不到**时是安全的(`if (XInputLibrary)` 不成立,指针继续指向 stub)✅;
- 但**DLL 在、某个导出函数取不到**时,`GetProcAddress` 返回 0 会被直接写进指针 → **NULL**,
  等于把 `2.2` 里 stub 提供的那层保护拆掉了,之后再调用就是"跳地址 0"。
- 完整的写法要给每个指针兜一次底:

```c
if(!XInputGetState) { XInputGetState = XInputGetStateStub; }
if(!XInputSetState) { XInputSetState = XInputSetStateStub; }
```

> 这台机器上 `XInput1_3.dll` / `XInput1_4.dll` / `xinput9_1_0.dll` **都在**(已实测),
> 所以现实里不容易撞上;但这正是"stub 模式"存在的理由,值得补上。

## 六、今天搞懂的概念

1. **"函数类型"和"函数指针类型"是两个东西。** `typedef DWORD WINAPI x_input_get_state(...)` 造出来的是前者,所以 `x_input_get_state*` 才是指针 —— 这也是为什么"同一段代码里有的地方写 `*`、有的不写"。
2. **宏的真正价值不是"少打字",而是"单一事实来源"。** 同一个宏拿来生成 `typedef` 和 stub 的函数头,签名就不可能漂移;而 `GetProcAddress` 返回的是**无类型指针**,签名写错编译器**不会**替你发现,要等运行期炸栈。
3. **`#define` 是纯文本替换**,从定义点往下全文件生效 —— 所以 `XInputGetState` 变成 `XInputGetState_`(证据:`pp.i` 第 318105 行);而带下划线的那个名字是**另一个 token**,不会被它改到。
4. **SAL 注解(`_In_` / `_Out_`)不进代码**:`cl -E` 之后它们整片消失。
5. **为什么必须"初值指向 stub"**:不初始化 = 0,调用 = 跳地址 0 崩。stub 是"没设备"的**安全答案**,而不是"留个 NULL 到处判断"。
6. **配套术语**:这套机制叫 **Run-Time Dynamic Linking(运行时动态链接/显式链接)**,对照的是 **Load-Time Dynamic Linking(隐式链接,靠 `.lib` 导入库)**;POSIX 的对应物是 `dlopen`/`dlsym`;链接器版的偷懒方案叫 **Delay Load(`/DELAYLOAD` + `delayimp.lib`)**。
