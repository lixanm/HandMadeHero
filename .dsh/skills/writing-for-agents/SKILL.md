# 写给 agent 看的文档

适用对象:`NOTES.md`、`.dsh\skills\*`、`explain\` 下任何会被 AI 读的文件。
**同一套判据对它们全部适用** —— 因为 agent 每次读它们、按同样的**过程**行动。

## 两种负载

- **上下文负载**:常驻在 agent 窗口里的东西(每个 `description`、`NOTES.md` 的每一行)。**每一轮都在花 token 和注意力**,不管它这次用不用得上。
- **认知负载**:人得记住"有哪些文档、什么时候去取"。**这不是要省掉的** —— 它是人的能动性的价格,花在需要人判断的地方。

## 指针 vs 缓存(最常用的一个判断)

一份文档要么当**指针**(说清"有什么、什么时候去取"),要么当**缓存**(把内容抄过来)。

- **环境本身就是真相源**:`HandMade.vcxproj` 里的编译参数、目录结构、`--help` 输出。抄它 = 缓存,只在"查一次很贵"时才值得;
- **值得缓存的**:没写下来的约定、某个选择**背后的原因**、没有任何配置会承认的坑;
- 判据:`NOTES.md` 里凡是"去 `HandMade.vcxproj` 看一眼就知道"的内容 —— **删掉,留指针**(`NOTES.md` §6 已经这么做了)。

## 单一真相源

一个意思只能有**一个**权威位置。重复会让维护成本翻倍,还会让这个意思在读者眼里**显得比它实际更重要**。

| 内容 | 权威位置 |
|---|---|
| 译名 / 术语 | `explain\!HandmadeHeroExplain\Day 001 - Day 004 术语表.md`(再上层是 `GLOSSARY.md`) |
| 编译 / 链接参数 | `HandMade\HandMade.vcxproj` |
| 关键决策与理由 | `.agents\adr\` |
| 当天发生了什么 | `explain\2026-9\` 的工作日志 |
| 每一集讲了什么 | `explain\!HandmadeHeroExplain\Day 00X ...md` |
| AI 自己的状态与坑 | `explain\!AI笔记\项目状态与交接.md` |

## leading word(用一个词锚住一片行为)

模型预训练里已有的词,作为 token 反复出现时会**锚住一整片行为**。找到"三处都在啰嗦同一件事"的地方,压成一个词:

- "我信得过、会在这个 bug 上变红的回路" → **红**(见 `diagnosing-bugs`)
- "先填满缓冲再按播放" → **填满**
- "快、确定性、低开销" → **紧**

原生词优先;自造词要付定义成本。**否定式提示会反向激活**:"别想大象" ⇒ 大象全在。
写**正面目标**("写一行注释"),而不是禁令;禁令只留给无法正面表述的硬护栏。

## 完成条件:可检查 + 有要求

- **可检查**:agent 能分辨"做完"和"没做完"。含糊的边界("理解了")会招来**提前完成** —— 注意力滑向"我完成了",而不是"真的做完了";
- **有要求**:"每一处修改都要能解释" 比 "列一个改动清单" 逼出的实际工作多得多;
- 最强的完成条件同时具备两点:**可检查 + 穷尽**。

## 修剪(否则默认结局是"沉积物")

文档默认会**沉积**:加一行显得安全,删一行显得冒险,于是层层叠上去,直到要找一棵活着的树得先挖穿化石。

逐句过三个问题:

1. **这一行还会影响这件事吗?** 不再影响 → 删;
2. **这一句是不是在说模型本来就会做的事?** 是 → **整句删掉**(不是删几个字);
3. **这段是"规则"还是"某次事故的经过"?** 事故 → 移去日志,这里只留规则。

`NOTES.md` 越接近"每条都是仍然生效的规则",越好。它的 §9(我做不到的事)与 §10(冲突顺序)是它最有价值的两节 —— 保持那种密度。
