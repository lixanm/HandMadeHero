# 0006 — 后备缓冲固定 1280×720,窗口拉伸靠 `StretchDIBits`

- **状态**:已采纳
- **日期**:2026-09-21(Day 005 代码落地)
- **相关**:`HandMade\code\win32_handmade.cpp`(`Win32ResizeDIBSection` / `Win32DisplayBufferInWindow`)、
  `explain\!HandmadeHeroExplain\Day 005 - Windows Graphics Review.md`、`explain\2026-9\2026-9-21.md`

## 背景

Day 3/4 的做法是:窗口一变(`WM_SIZE`),就按**客户区大小**重建后备缓冲 —— 缓冲尺寸跟着窗口走。

Day 005 现场发现这带来一个真 bug:`StretchDIBits` 的**源矩形**被写成了"缓冲尺寸",而正确语义是
"从缓冲里取哪一块" ⇒ 窗口尺寸变化后画面完全错乱。修法有两种:把源矩形改成缓冲尺寸(继续耦合),
或者**把渲染分辨率与窗口尺寸解耦**。

选后者,还有一个更重要的理由:**游戏逻辑需要稳定的坐标系**。
如果缓冲跟着窗口变,那么"换个屏幕尺寸 ⇒ 视野、碰撞、UI 布局全变" —— 这对以后要做的地图与关卡是灾难。

## 决定

1. **后备缓冲固定为 1280×720**,只在启动时分配一次(窗口大小与它无关);
2. 用 **`StretchDIBits`**(而不是 `BitBlt`):源矩形永远是 `0,0,1280,720`,**目标矩形**才是当前客户区尺寸;
3. 窗口尺寸变化**不再重建缓冲** —— 画面被拉伸显示(宽高比校正留 TODO);
4. 渲染坐标体系从此固定:像素坐标、碰撞、UI 都以 1280×720 为准。

## 后果

**好的**

- 画面尺寸与游戏世界解耦 ⇒ 关卡/碰撞/UI 的坐标稳定,不会随窗口变化;
- 为将来"固定分辨率渲染,再整体放大/加黑边"铺好了路(只改目标矩形与比例);
- 顺便修掉了那个"参数写反"的潜伏 bug。

**代价 / 需要盯着的**

- 现在窗口拉伸会**变形**(宽高比校正还没做,代码里留了 `//TODO:宽高比校正`);
- `WM_PAINT` 与主循环都做整窗 blit ⇒ 有一点重复劳动(可接受;`WM_PAINT` 那一路还必须保留,
  否则脏区域不会被 validate,系统会一直发 `WM_PAINT`);
- 以后要做"整数倍缩放/像素完美"时,得自己算目标矩形(不能用整窗拉伸)。

## 考虑过的替代方案

| 方案 | 为什么不选 |
|---|---|
| 缓冲跟随客户区大小(Day 3/4 的做法) | 视野/碰撞/UI 会随窗口变化;而且窗口一改就要重新分配内存 |
| 固定分辨率 + `BitBlt`(1:1 拷贝) | 窗口比缓冲大时只能画一部分,无法缩放 |
| 让窗口**不可缩放**(固定尺寸) | 用户会想最大化;而且以后全屏/分辨率切换同样需要缩放能力 |
