# 0005 — 不用任何引擎/框架;按 C 风格写 C++(不用 STL / 异常 / RTTI)

- **状态**:已采纳
- **日期**:2026-09(项目起点)
- **相关**:`README.md` 开头、`HandMade\HandMade.vcxproj`(`/GR-`、`/EHa-`、MultiByte)、`explain\win32-api-guide.md`

## 背景

项目的第一句要求就是"**不用任何框架、不用任何引擎**,把 Windows 平台层和游戏引擎全部自己写出来"。
那么"用什么语言子集写"就不是风格偏好,而是**项目目标的一部分**:用到的东西越少,自己写的比例越高、
心智模型越小、也越能看清底层在做什么。

同时,教程(Casey)本身就是"`win32_handmade.cpp` 是 C++ 文件,但按 C 的风格写"。

## 决定

1. **不引入引擎/框架**(Unity/Unreal/SDL/GLFW/SFML … 一律不用);
2. **按 C 风格写 C++**:
   - 不用类/继承/模板(用 `struct` + 自由函数,函数名带模块前缀);
   - **不用 STL 容器/字符串**(目前没有一条 STL include);要容器就自己写(以后几集才遇到);
   - **不用 C++ 异常**(`/EHa-`)、**不用 RTTI**(`/GR-`);
   - 字符串用 `char *`(**字符集 = MultiByte**,与视频里的 ANSI 风格一致);
   - 错误处理走**返回值**(`HRESULT` / `GetLastError`),不靠异常;
3. **库只做两件事**:平台 DLL 的运行期加载、以及官方 SDK 的声明(`windows.h` / `dsound.h` / `xinput.h`)。

## 后果

**好的**

- 心智模型小:每行代码执行什么都看得见(反汇编里也一样);
- 没有隐藏行为 —— 没有构造函数/析构函数在背后分配、复制、抛异常(音频/渲染路径上这点很重要);
- 编译快,调试器里的调用栈和源码一一对应;
- 和教程逐字对应,`Day N` 的进度可以直接对照。

**代价 / 需要盯着的**

- **要自己写容器、字符串、内存管理**(以后几集就会遇到 —— 这是学习目标,不是意外);
- **不能用 RAII 自动清理**,所以资源配对必须显式且写对:`GetDC`/`ReleaseDC`、
  `BeginPaint`/`EndPaint`、`Lock`/`Unlock`、`VirtualAlloc`/`VirtualFree`;
  ⇒ 这也是为什么"借还范围要短、不能跨越提前 return"成为一条规矩(见 `Day 008` 文档 §2 与 `NOTES.md` §6);
- 有些现代 C++ 的便利(`std::vector`、`std::string`)要自己造,容易写出 bug —— 慢,但可控;
- 一旦打破(比如"就引一个 `std::vector`"),**整条边界就模糊了** ⇒ 引入任何第三方/标准库组件都要先问用户
  (`NOTES.md` §4 的 C 类)。

## 考虑过的替代方案

| 方案 | 为什么不选 |
|---|---|
| 用 SDL/GLFW 做平台层 | 与"自己写平台层"的项目目的直接冲突 |
| 用 C++ 子集但保留 STL 容器 | 会引入隐藏分配与异常路径;而且"哪些能用"的边界解释成本高于收益 |
| 直接写 C(`.c` 文件) | 大体等价,但教程与 SDK 头文件都按 C++ 组织(COM 接口就是 C++ 声明);用 `.cpp` + C 风格最省摩擦 |
