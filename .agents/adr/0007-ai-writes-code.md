# 0007 — AI 可以直接写代码(取消"手敲优先"的只读约束)

- **状态**:已采纳
- **日期**:2026-09-30
- **相关**:`NOTES.md` §1(已重写)、[0001](0001-hand-typed-first.md)(**被本 ADR 取代**)、`explain\2026-9\2026-9-30.md`

## 背景

从项目开始到 2026-09-30,这个仓库的元规矩是"**代码必须用户手敲,AI 默认只读**"(见 [0001](0001-hand-typed-first.md))。
它的理由不是效率,而是**学习**:手打出来的代码才在脑子里,才问得出具体问题。

2026-09-30 用户宣布:

> "把只有我手写代码的约束去掉,我要依靠你的力量了。"

当天可查的上下文:

1. 用户已经把 Day 008 的环形缓冲 / 方波 / `Play` **全部手打完成**(757 行),并自己提交了(`661157d`);
2. 同一天刚发生"**两套构建配置漂移**"(`build.bat` vs `.vcxproj`)—— 这类**苦力活**本可以更快做完;
3. 平台层剩下的段落越来越像重复劳动。

🟡 **我的理解(用户未明说)**:这不是放弃学习,而是**把"打字"这个瓶颈拿掉,把精力留给设计与判断**。
如果理解错了,用户随时可以恢复 0001 —— 恢复的开关写在 `NOTES.md` §1.3 最后一条。

## 决定

1. **AI 可以直接改 `HandMade\code\` 里的代码,不再需要每次批准**(`NOTES.md` §1);
2. 分**三档**:
   - **直接做**:读、搜、编译、跑、反汇编、写文档;
   - **先说一句再做**(不必等批准):改代码、改工程文件、新建/移动文件;
   - **必须等批准**:删文件、改 git 历史、引入第三方库/工具链、commit / push(§7);
3. **保留"讲清楚"**:非平凡改动要说明"为什么这么写";关键取舍摆出来让用户拍板;
   用户随时可对某个文件或某一段说"**我自己打**",那一次就回到只读;
4. **保留三条底线**:留退路(`git status` 先看)、不降低编译标准(`/W4 /WX` 不许动)、防编辑器覆盖(§1.5);
5. ADR 0001 标记为**已废弃,不删除** —— 它记录了那一个月的真实做法与理由,也是本 ADR 的背景。

## 后果

**好的**

- 平台层的样板代码、调试脚本、工程配置不再占用用户的时间;
- AI 可以在**真实代码**上验证(编译 / 反汇编 / 跑起来),而不是只能"给建议";
- 用户可以把精力放到**类银河城的设计**上 —— 那一层没人能替他做。

**代价 / 需要盯着的**

- **手敲带来的直觉不再自动积累** —— 这正是 0001 真正想要的东西。
  缓解:`§1.3` 的"讲清楚" + 用户随时可以把某一段收回去自己打;
- 代码里会混入"不是用户写的"风格与习惯 ⇒ 对自己代码库的熟悉度会下降。
  缓解:**改动保持小步**,并在日志 / ADR 里留下"为什么";
- AI 出错的机会变多(同一天它已经制造过一次 `CRCRLF` 文件损坏事故)⇒ "留退路"与"要证据"两条更要紧。

## 考虑过的替代方案

| 方案 | 为什么不选 |
|---|---|
| 保持只读(0001 原样) | 用户明确要求取消;平台层的重复劳动确实是瓶颈 |
| 只让 AI 写"平台层 / 工具",游戏层仍手敲 | 更精细,但边界每天都在变(例:音频算平台层还是引擎层?),维护成本高。🟡 以后想这么做再开一条 ADR |
| AI 写代码、用户逐行 review 后才落盘 | 相当于把"打字"换成"读 diff",用户的时间并没有省下来 |
| AI 全权(连 commit / push 也自主) | 不可逆操作的风险与收益不成比例 —— 保留批准这一档 |

## 备注

- 旧 ADR 的**技术结论不受影响**:0002(只跟平台层与引擎层)、0003(构建真源)、0004(不链 xinput)、
  0005(C 风格无引擎)、0006(固定 1280×720)全都照旧;
- 本 ADR 只改变"**谁来写代码**",不改变"**写什么**"。
